# Nori 决策记录

记录与最初《macOS 清理工具 Swift 重写方案》的有意偏差及其安全论证。每条记录一个决定：为什么偏离、以什么条件成立。

## DR-1 · App-only 形态（2026-09-27 确认）

**决定**：不实现方案 §0 的命令行（含 TUI）前端与 Homebrew 分发，只维护 SwiftUI App。
**理由**：产品已有自己的客户端载体，功能层（Services/策略/安全）与前端解耦，未来补 CLI 时可直接复用；不为不存在的消费者维护参数面（`--dry-run/--yes/--json` 等）。
**约束**：任何新增能力必须先落在功能层（可测试的 Services），不得写死在视图里，保证未来第二前端的可行性。

## DR-2 · 菜单栏常驻与定时能力（追认）

**决定**：追认超出方案 §1.2「不做常驻后台监控、定时清理、通知或菜单栏常驻」的部分：菜单栏常驻、每小时自动清理调度、流量监控、剪贴板历史。
**安全前提**（缺一即应回退本决定）：
- 自动清理只走 `automatic` 执行模式：执行前重新读取完整运行态快照，快照不完整直接放弃本轮（fail-closed）。
- 自动规则不得与模型、用户会话、Docker 数据或系统根目录重叠（`isForbiddenAutomationPath`）。
- 自动清理沿用与手动清理完全相同的删除漏斗（身份核对、白名单、打开文件检查）。

## DR-3 · 部分扫描结果保留展示（替代方案 §2.5）

**决定**：扫描超时/不完整时不整批丢弃结果，保留已确认完成的部分。
**安全等价论证**：方案要求整批作废的目的是防止半截结果流入删除。当前实现满足同一不变量：未完成目录单独列入 `deferredPaths` 展示；`cleanupScanComplete == false` 时所有条目强制取消勾选（不可执行）；不完整快照不写入完整结果缓存（5 分钟缓存复用不会继承）；执行前仍有逐项身份复核。UX 更好（用户能看到扫描到了哪里），安全性不降。

## DR-4 · 处置矩阵按方案 §5.3 对齐（2026-09-27 修正）

**决定**：修正两处与方案相反的处置：
- **安装包（installer）→ 移入废纸篓**（原实现为永久删除）。安装包可能是用户唯一的副本。
- **项目产物（purge）→ 永久删除**（原实现经 bridge 移入废纸篓）。构建产物可本地重建，进废纸篓只会让用户再清一次。

落地方式：`AppState.permanentFamilies = [.clean, .purge]` 是处置的唯一事实来源，确认文案（`confirm.cleanupPermanent.*` vs `confirm.apply.trash.*`）、bridge 环境变量（`SIMPLEMOLE_DELETE_MODE`）与执行汇总（`cleanup.execution.summary.permanent`）全部从它派生。移入废纸篓失败时绝不降级为永久删除。

## DR-5 · 删除出口集中与静态审计（2026-09-27 新增）

**决定**：永久删除不再使用路径字符串 API，改为 fd 链删除：从 `/` 逐级 `openat(O_NOFOLLOW|O_DIRECTORY)` 打开，最终句柄上核对 `(device, inode)` 后在已打开描述符下递归 `unlinkat`，全程不重新解析路径。`script/audit_destructive_sinks.sh` 纳入 `test.sh`：Swift 侧底层删除调用只允许出现在白名单文件（NativeCore 为用户数据唯一漏斗，其余仅清理应用自建临时文件）；bridge 侧 `mole_delete` 必须显式携带身份参数，`rm -rf` 只允许作用于脚本自建目录变量。

## DR-6 · 系统数据降级为清理页入口（2026-09-27；流量部分由 DR-8 取代）

**决定**：
- 系统数据（root 拥有的日志/报告/缓存/更新残留）不再占顶级 Tab，降级为「硬盘清理」页头部入口，以 sheet 承载原有整页视图；扫描/删除管线（特权预览 + NUL 计划 + SHA-256 + 身份复核）不变。
- 流量页定名「代理流量」（en: Proxy Traffic）。该页的产品定位是代理流量归因（节点/DIRECT 拆分、规则链路、按应用归属），不是通用流量监控；无 Clash/mihomo 控制器时是降级模式，横幅明示"仅系统口径的按应用流量"。

**理由**：系统数据日常收益小且每次扫描需管理员授权，撑不起顶级 Tab，但它是应用唯一能清 root 数据的表面，能力保留、入口降级；通用按应用流量统计与活动监视器重合，没有独立场景，Clash 绑定正是使用场景。nettop/lsof/路由层保留为归因底座与无控制器兜底。
**约束**：不做通用化改造；若未来支持其他代理内核，沿 Clash REST API 协议兼容（mihomo/sing-box clash-api 均同协议），不新增第二套控制器适配。

## DR-7 · 产品身份全面切换为 Nori（2026-09-28 新增）

**决定**：Bundle ID、可执行文件、构建产物与数据目录由 ForgeSweep 统一切换为 Nori（`com.nori.app` / `Nori.app`），可见名称与内部身份不再分叉。
**迁移**：`BrandMigration` 在首次启动时迁移 `com.forgesweep.app`（及更早 `com.simplemole.app`）的 `SM*` 偏好，并搬移 Application Support / Caches / Logs 三个数据目录；`release_identity.sh` 一次性把本地私钥归档从 ForgeSweep 路径搬至 Nori 路径。
**保留**：已发布的自签名 release 证书（CN "ForgeSweep Release Signing"，SHA-1 指纹 `ABF7136A66689BF6437F7C4252A3168401FF33F6` 不变）继续为 `com.nori.app` 签名——指定要求仍钉住同一证书根；GitHub Actions secrets（`FORGESWEEP_SIGNING_P12_*`）与 `FORGESWEEP_FULL_DISK_AUTHORIZED` 环境变量保持原名，避免破坏已配置的发布流水线与权限门禁契约。
**代价（接受）**：Bundle ID 变化使既有 TCC 授权（完全磁盘访问、屏幕录制等）在升级后失效，需重新授予一次；本地开发身份换用 "Nori Local Signing"，首次构建重新生成。

## DR-8 · 简化扫描范围与通用流量监控（2026-09-28）

按用户最新要求，磁盘分析只保留用户空间（默认）、根目录、自定义目录三个范围。长期关注、开发项目雷达、项目休眠及相关自动化规则退役；普通目录自动清理和每日/每周安全清理继续保留。旧规则逐条读取，退役类型不再调度，不影响其余计划。

流量页改名「流量监控」，删除 Clash 配置发现、控制器请求、节点/DIRECT 归因、专属历史账本和相关界面。保留 nettop 应用字节差分、lsof 当前连接、路由分类及物理/隧道接口计数；不同层级的计数不相加。新会话使用独立历史文件，不将旧代理统计混入系统采样。

## DR-9 · 自动清理规则不随品牌迁移 + 生效可见性（2026-09-30）

**决定**：
- `BrandMigration` 迁移旧品牌 `SM*` 偏好时排除 `SMAutoCleanupRules`：自动清理规则携带创建时逐目录记录的「仅可再生内容」授权与根目录身份，新装应用不得静默继承旧品牌的自动删除授权（旧机器升级后表现为"新装就有内置规则"）。
- 规则开启（或已开启规则调整策略）时立即执行一轮调度（`force: true`），不再只清六小时限频静等下一个小时定时器；规则面板逐条展示最近一次失败原因，缺完全磁盘访问时显式横幅提示。
- 清理页类目/路径与磁盘分析行显示"已定时"标记（`autoCleanupRuleCovering`，父子目录均算被管理）；磁盘分析的大文件/图片/视频行新增按所在目录发起定时清理的入口（`cacheVerified: false`，创建后仍需人工确认可再生）。
- 手动添加目录后不再自动预览（未确认可再生前预览必然失败），改为引导用户先勾选确认、预览、再开启。

**安全前提不变**：规划器与 `app_auto_apply.sh` 的删除漏斗（身份核对、白名单、打开文件检查、fail-closed）完全未动；新增的只是可见性与触发时机。

## DR-10 · 自动清理规则的版本继承契约（2026-09-30）

**场景**：同一产品（`com.nori.app`）从版本 1 升级到版本 2，用户在版本 1 配置的定时清理规则必须完整继承：目录、策略、参数、启用状态与运行历史全部保留，已启用的规则升级后继续按调度执行，无需用户任何操作。UserDefaults 域随 Bundle ID 存在于 `~/Library/Preferences`，覆盖安装不会触碰，这是继承的物理基础。

**存储格式契约**（保证两个方向的版本兼容）：
- 持久化格式保持「规则对象的 JSON 数组」，不引入信封/版本包裹——数组格式配合字段纪律天然双向兼容：新版本新增字段必须 `decodeIfPresent` 可选（旧数据缺键可读），JSONDecoder 默认忽略未知键（新数据多键旧版本也能读）。改字段名或类型等于放弃继承，禁止。
- 安全版本（`safetyVersion`）过期的旧规则解码后保持「未确认、不可执行」，但**存储中的授权数据（版本号 + 根目录身份）原样保留**，中途保存也不销毁——安全模型升级后用户重新勾选一次「仅可再生内容」即可恢复规则，不需要重建；回滚到旧版本数据同样完好。

**损坏防护**：
- 单条规则字段损坏时按条拯救（`JSONSerialization` 逐条尝试解码），其余规则照常加载，不再一条坏全批丢。
- 整体无法解码的数据在覆盖前快照到 `SMAutoCleanupRulesBackup`，升级路径上的意外损坏可恢复。

**边界**：版本继承指同 Bundle ID 的升级；跨品牌首次安装（SimpleMole/ForgeSweep → Nori）仍不迁移自动清理规则（见 DR-9）。

## DR-11 · 系统优化页下架与能力分流（2026-09-30）

**决定**：系统优化页整体下架。21 项维护任务按价值分流，其余随页面退役：

- **数据库维护 → 硬盘清理页**（扫描完成后体检的"系统数据库维护"卡片，逐项确认后执行）：SQLite 压缩（Mail/信息/Safari，完整性检查通过后 VACUUM）、通知历史（>50MB 清 30 天前）、使用记录知识库（>100MB 清 90 天前）、下载隔离历史、30 天前的窗口保存状态。执行层保留在 `NativeCore+Optimize.swift`（`SystemMaintenanceItem/Row` + `inspectSystemMaintenance`/`runMaintenanceTask`），白名单与预检-执行证据绑定语义不变。
- **网络与服务修复 → 开发环境页**：DNS 缓存刷新、网络栈重置（复用 `app_optimize_admin.sh` 提权桥接）；QuickLook/图标服务/LaunchServices 修复（免提权，`runMaintenanceTask`）。
- **新增能力（开发环境页）**：环境变量体检（`ShellEnvAudit`：PATH 死段/重复段、路径型变量失效、未守卫的失效工具初始化行；改写或删除前逐文件备份）；网络环境出厂重置（`app_net_reset.sh`：关全部代理、DNS 恢复自动、忘记已存 Wi-Fi、删非"自动"位置、恢复 /etc/hosts、/etc/resolver 自定义移入备份、刷 DNS 缓存；修改文件先备份，需管理员授权 + 明确列出动作的确认弹窗）。
- **随页面退役**：损坏偏好/边栏列表修复、Spotlight 孤儿规则、legacy overrides、.DS_Store 开关、periodic 补跑、home 权限修复、Spotlight 重建、磁盘校验、登录项/launch agents 报告（`app_optimize_admin.sh` 中对应任务保留但无入口，未来按需恢复）。

**安全前提不变**：数据库维护仍先只读体检（预检-执行证据绑定、Mail/Safari/信息运行中跳过、白名单尊重）；出厂重置只删"系统默认之外"的内容且全部先备份；提权桥接沿用 uid 校验与非 root 拒绝（`test_optimize.sh` 保留桥接安全检查，Swift 任务目录测试随页面移除）。
