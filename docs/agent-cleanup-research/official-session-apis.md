# 其他 Agent 的官方会话清理能力

核对日期：2026-10-13。只读取官方文档和官方源码，未启动被研究的 Agent、未调用删除接口、未操作真实历史。[首批 OpenCode/Copilot/Gemini 适配代码](history-adapters.md) 已写入，但按用户安排暂未校验，入口保持关闭；本研究不代表各接口已经可在安装版中使用。

**结论：可以按产品适配，不能套用一个目录删除规则。** 已确认多款产品有会话删除 SDK、服务协议或原生 CLI；另一些只支持项目清除、保留策略、界面操作或云端删除。以下区分：**公开 API/SDK、原生 CLI、原生保留策略、内部实现/UI、云端能力、未确认**。官方源码实现不等于已承诺跨版本兼容；在线文档是本次读取时的内容。

## 接入边界

1. 优先适配 OpenCode、Copilot SDK、Gemini CLI 等明确的本地入口。其余已确认入口先检查安装版本和实际能力，不凭命令名或同一品牌推断兼容。
2. 新旧 Cline、新旧 Kimi、Kiro CLI/IDE、Devin CLI/桌面/云端分别识别；新版接口不代表它会管理旧版全部残留或另一宿主的历史。
3. 列表需显示项目、时间、会话 ID 与本地/远端来源，识别运行中、置顶、自动化、工作树和子会话关联；关联状态无法确认时不放行删除。接口能取消运行也不意味着清理器应取消用户工作。
4. 先备份正文及关联状态；export 一份 Markdown 不等于可完整恢复的备份。未确认恢复契约时明确提示这一点。
5. 删除后重新查询 ID，必要时核对产物回收。**成功退出码、归档、断开连接、清上下文均不能替代删除验证**；Gemini 已确认需要特别处理 stderr 与退出码的差异。
6. Amp、Grok、Factory、Cursor Cloud、Qoder Cloud、Devin Cloud 的远端动作要单独展示和授权，不能混进普通本机缓存清理；官方删除也不保证同步客户端的全部副本立即回收。
