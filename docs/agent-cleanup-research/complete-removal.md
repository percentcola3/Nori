# Agent 完整卸载与残留

日常清理与完整卸载有不同的授权范围。Safe/Review 的文件清理继续保护会话、数据库、凭据、配置与技能；删除 CLI 程序不等于删除这些数据，也不能因为配置目录存在就报告程序仍安装。

2026-10-20 合并说明：面向用户的软件、CLI 和 Agent 入口现共用 [可选整份应用数据卸载](whole-app-data-removal.md)，逐项选择默认全不选，真实项目代码保留；已卸载数据也可在「卸载垃圾」中扫描。下文记录独立 `AgentRemovalService` 的整根计划与执行约束，其保留的 API 不替代上述入口的选择授权。

## 统一入口

所有 `AgentCatalog` 产品共用完整移除服务。Agent 页的软件卸载、批量 CLI 卸载和软件页的 Agent CLI 卸载成功后，会单独预览仍存在的独占数据。未安装产品也可从 Agent 页的“完整移除残留”进入同一流程。预览必须列出实际路径，说明历史、登录配置、技能、工作树可能丢失；确认后只移入废纸篓，不支持永久删除。

软件卸载仅约束选中的安装渠道。其他渠道、桌面版或扩展仍存在时保留共享数据。普通非 Agent CLI 由已匹配的包管理器卸载；Go 工具仅移动确认的二进制。任意 CLI 的用户数据不能由包名猜测归属，也不会把 npm/Homebrew 等共享缓存、依赖或未知包装脚本当作该 CLI 的独占数据删除。

## 执行边界

- 只从已知产品数据根生成计划，禁止主目录、通用 `.config`/`.cache` 等宽泛根以及归属不明的自定义路径。
- 计划记录原路径、身份、元数据及整棵目录的元数据指纹。执行重新验证安装存在性、共享消费者、白名单（含子项）、物理父目录、进程和打开文件。
- 确认之后出现的新路径不加入计划；原目录发生变化则保留并要求重新预览。
- 内部符号链接随根搬走，不跟随删除目标；外部消费者引用到根内的技能/MCP 内容时保留根。
- 完整根必须属于当前用户。安装器在其中创建的其他属主子项仍记录到元数据指纹，只要整树可验证即可随根移动，不更改属主或权限。
- 未知、无法读取或复扫不完整时明确报告保留/未确认，不能仅凭部分移动成功声称清理完成。
- 复扫同时刷新程序、数据与存储记录；没有可移项目时也刷新，避免成功卸载后继续显示旧行。

`AgentRemovalService` 独立执行完整移除；没有放宽 `NativeCore.applyCleanup` 的日常受保护数据边界。

当前废纸篓操作使用系统 `FileManager.trashItem` 以保留 Finder 的恢复语义。最终校验和系统按路径移动之间仍存在极窄的并发改名窗口；多次身份/物理父目录复核降低其影响，但不宣称抵御同一用户有意发起的路径替换竞态。

## Hermes 安装证据

新增 `hermes`、`hermes-agent`、`hermes-acp` 入口及 `~/.hermes` 数据归属。日常保护配置、`.env`、认证、state.db 家族、会话、记忆及用户音频/图像；缓存与日志仅列为 Review。

原生安装根为 `~/.hermes/hermes-agent`。识别程序根需要公开的 pyproject 项目名/入口、源模块、bootstrap 标记和 venv（或 `.venv`）证据。外部启动器仅接受指向该已证明入口的已知链接或严格 wrapper，不执行它来探测。pipx/uv 环境还需 dist-info 项目名和 console_scripts 证明。只剩 wrapper、OpenCode 插件 node_modules 或 Factory 的 rg，均不授予整个数据根的程序卸载权限。

公开来源：[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)，以及本机已安装版本的公开 `pyproject.toml`、安装说明、模块/入口文件元数据。没有读取凭据文件内容；未验证 `HERMES_HOME` 自定义路径契约，因此不扩大到任意位置。

## 验证与恢复

`script/test_agent_cli_ownership.sh` 验证安装证据、入口合并、失效/外部链接和安装渠道边界；`script/test_agent_removal.sh` 用一次性目录及模拟废纸篓验证完整移除、白名单、共享引用、失效计划、占用、失败与恢复。工作流测试验证完整移除需要独立确认，普通清理不获得额外删除权限。

移入废纸篓不表示磁盘空间已释放。恢复时先退出产品，从废纸篓恢复原目录/启动器，再重新扫描；不要覆盖重新安装后产生的新数据。
