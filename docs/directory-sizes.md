# 目录硬盘占用：后台计算与缓存

目录页显示文件实际分配的磁盘空间。文件只读取元数据；目录逐步汇总其子项，不为计算占用打开文件正文。已有结果会保存并复用，重新打开目录时可以先看到上次的数值，后台再补齐或更新。

计算不依赖目录 tab 是否可见。切换到其他页面后，已安排的后台任务继续处理；退出 Nori 后任务停止，重新启动再恢复需要的检查。它用于补齐已浏览或搜索到的目录占用，不承诺持续扫描整台 Mac。

## 更新与时效

- 首次计算逐步补齐结果，尚无结果的目录显示“计算中”。
- 能够观察到的文件变化会触发相关占用更新；目录自动刷新和切换目录优先复用缓存，不把所有已知目录重新从零扫描。
- 点击“刷新目录与占用”会主动校准当前范围；后台更新期间仍显示上次结果。
- 每 6 小时安排一次校准，补上未及时发现的变化。这个周期只在 Nori 运行期间推进；检查和大目录计算均在后台完成。
- 缓存与刷新状态彼此独立。后台正在更新，或暂时不能确认当前占用时，继续显示上次结果及其计算时间。

页脚显示后台更新或校准状态。将鼠标停在占用数值上，可查看上次计算时间和该数值是否正在更新。文件名搜索索引与占用缓存是两个独立功能，“更新索引”用于搜索覆盖范围；占用由后台计算维护。

## 数值的含义

| 显示 | 含义 |
| --- | --- |
| 计算中 | 尚未取得可用结果，已安排后台计算。 |
| 数值旁的进度指示 | 正在更新；当前数值仍是上次计算结果。 |
| 数值旁的时钟标记 | 当前显示缓存，最新占用尚未确认。 |
| `≥` 数值 | 已知占用的下限，部分子项未能读取。后台更新时仍保留下限标记。 |
| 无法读取 | 未取得可用占用结果。 |

隐藏文件也计入目录占用；隐藏开关只控制目录页的显示。符号链接只计算链接本身，不跟随目标；目录树内重复硬链接只计算一次。未下载的云目录、没有权限的子目录和跨磁盘挂载点不会强行读取，结果保留为下限。

“硬盘占用”不等于删除后必然释放的空间。APFS 共享数据、克隆与快照可能影响最终可释放量；将项目移入废纸篓也不会立即释放空间。

## UI 数据约定

`DirectoryBrowserModel` 提供 `sizeStates`、`sizeUpdatedAt` 和 `sizePartialIDs`。更新时间仅来自已经完成的计算；刷新开始不能把更新时间改成当前时间。`sizePartialIDs` 独立保存下限属性，避免 `.updating` 或 `.stale` 状态掩盖不完整结果。

行只接收自身占用状态与时间戳，格式化日期遵循界面环境的 locale。缓存读取、后台调度、取消与校准均由服务/model 负责，SwiftUI 行不启动文件扫描。减少动态效果与减少透明度的玻璃回退沿用目录页已有约定。

## 后台维护方式

服务保存目录成员和文件元数据的快照。普通变化只刷新受影响的分支，再更新祖先汇总；未变化的子树直接复用已有汇总。校准会重新核对嵌套文件的修改时间、状态变化时间和分配块数，复用成员未变化的目录列表，因此文件正文被原地修改也能被发现。

递归监听使用 macOS FSEvents，包括点开头的子目录。事件只作为失效提示，最终占用以文件系统元数据为准；监听范围变化时重放尚未交付的日志，丢失事件或挂载变化会请求校准。第一次读取缓存时先显示旧值，再核对应用退出期间的变化。

持久化目录快照最多保留最近使用的 128 个根目录；当前列表可以继续保留更多轻量数值和监听，筛选不会因持久化容量限制而反复计算。后台每分钟检查哪些目录已满 6 小时；失败的定时重试至少间隔一小时。可见目录和发生变化的目录优先于历史目录的定时任务。

缓存位于 `~/Library/Application Support/Nori/DirectorySizes/state.json`，使用原子写入。该专用缓存目录的写入不会触发自身反复刷新。取消或扫描期间发生新变化时，不会把尚未确认的快照写成最新结果。第一次无法读取的目录只保留观察记录，不用零占用代替未知值。
